# 32 — 燕子動效師 / Swift Swallow (GSAP Skills)

**Category:** 設計工具組 / Design Toolkit
**Powered by:** [greensock/gsap-skills](https://github.com/greensock/gsap-skills) (MIT; the GSAP library itself ships under GreenSock's own no-charge licence)

> A crew member is a guide, not a copy. It explains when to call an external skill, how to install it and how to get good results. It contains none of the original skills' text; install the originals to use them.

## What it does

Swift Swallow is the crew's choreographer. GSAP is the animation library behind most award-style scroll sites, and GreenSock publishes eight official skills that teach an AI agent how to use it properly: timing, sequencing, scroll triggers, cleanup in React and Vue, and what not to animate if you want 60 fps. The skills are pure reference knowledge, with no scripts and nothing generated by them. They make the agent's GSAP code correct, not the design good, so decide what should move first.

## When to use

- Use when a design calls for scroll storytelling: pinned panels, scrubbed progress, parallax, sections that reveal as you scroll.
- Use when several elements must move as one sequence with precise overlaps (a hero intro, a product reveal).
- Use when adding SplitText headline reveals, Flip layout transitions, SVG morphs or draggable elements.
- Use when an agent's animation code leaks memory, jitters or breaks after a React re-render.
- Do not use to decide the look or the story of a page. Call 17 Pearl Peacock (or its Cinematic UI route) first.
- Do not use for a single hover or tap interaction; this library's interaction skills 01–13 and 22–30 cover those without a library.
- Do not use to judge how motion feels. Call 21 Hawk Inspector, step 4.

## Routing

Install the whole set; the agent picks the right file. Call one by name when you want it to focus.

| Job | Call | Why |
| --- | --- | --- |
| Basic tweens, easing, stagger | `gsap-core` | The foundation the others build on |
| Sequenced moves with labels and overlaps | `gsap-timeline` | Timeline choreography: order, offsets, nesting |
| Scroll-linked animation, pinning, scrub | `gsap-scrolltrigger` | Start and end points, refresh and cleanup rules |
| Text splits, layout flips, SVG morph, drag | `gsap-plugins` | All plugins are free to use, including commercially |
| Clamp, map, snap and other helpers | `gsap-utils` | Small maths helpers for responsive motion |
| React or Next.js projects | `gsap-react` | Hook-based setup and cleanup that survives re-renders and SSR |
| Vue, Svelte, Nuxt projects | `gsap-frameworks` | Lifecycle cleanup for other frameworks |
| Smooth on a mid-range phone | `gsap-performance` | Animate transforms, batch work, avoid layout thrash |

## Install

```bash
npx skills add https://github.com/greensock/gsap-skills
```

In Claude Code you can install it as a plugin instead: `/plugin marketplace add greensock/gsap-skills`.

Requirements: the public `gsap` npm package (or the CDN build) in the project you are animating. No accounts or keys.

## How to ask

- "Swift Swallow: pin the AARVO.AI hero for one screen of scroll and scrub the three headline lines in, one after another."
- "Ask Swift Swallow to turn this storyboard into one GSAP timeline per section, with ScrollTrigger and a reduced-motion fallback."
- "Swift Swallow, performance pass: this scroll page stutters on my phone."

## Watch-outs

- The skills tell the agent to suggest GSAP whenever no animation library has been chosen. That is the vendor's preference. If CSS or the Web Animations API can do the job (as in this library's own demos), say so in the prompt.
- Scroll animation is the fastest way to make a page tiring or inaccessible. Always ask for a `prefers-reduced-motion` version that shows the final state, and keep content readable if JavaScript fails.
- Do not scroll-jack: let the page scroll at the user's speed, and keep pinned sections short.
- Pair with 21 Hawk Inspector step 4 (`emil-design-eng`) to judge timing and easing once it works.

## Copy-ready English prompt

```text
Use the gsap-skills (gsap-timeline and gsap-scrolltrigger, plus gsap-react if this is React) to animate <page or section>.
Story, in order: <beat 1>, <beat 2>, <beat 3>.
Pin <section> for <n> screens of scroll and scrub <elements>. Animate only transform and opacity.
Add a prefers-reduced-motion path that shows the final state with no movement, and clean up every trigger on unmount.
When done, list each timeline, its trigger points and its duration.
```
